OVERVIEW OF THIS UPDATE (v2.1.0):
--------------------------------------------------------------------------------
This release addresses critical WAN performance, network reliability, and UI updates:
1. FIX WAN TIMEOUT CANCELLATION FOR REMOTE UNITS (Shimoga, Jaipur, etc.):
   - Problem: Remote hospital clients aborted /api/units after 4.45s with 0 bytes over WAN.
   - Solution: Client-side fetch AbortController timeout extended from 4.5s to 30.0s.
   - Server Optimization: Built-in Gzip stream compression enabled on the Node.js
     backend (compresses JSON payloads > 1KB down to ~8-12KB, 85% bandwidth reduction).
2. REMOVED "14 Unit & Unit Heads" TAB:
   - Sidebar cleaned for Super Admin & Operations Team; units are seamlessly managed
     through the executive matrix and inspect modals.
3. BOTTLENECK FILTERS:
   - Added explicit "Not started" and "In progress" filters alongside "Active", "Completed",
     and "All" with real-time badge counts.
4. EVIDENCE CONTAINER (Executive Dashboard):
   - Replaced bottom 3 static panels with an interactive Clinical & Operational
     Evidence Approval Container featuring Before/After photo proof, lightbox, and approvals.
5. MONTHLY STATS DATEWISE & MONTH FILTER:
   - Added interactive Month picker and Start/End Date range filters to dynamically
     filter bottlenecks according to months of input across all 14 hospital units.
6. CATEGORIES & AUDIT LOGS:
   - Dedicated "Categories & Depts" and "Audit Logs" real-time activity views.

DATABASE NOTE (IMPORTANT):
- Your existing PostgreSQL database and records are 100% PRESERVED.
- Automatic schema migration and seeding run safely on container boot.
- NO manual SQL migration scripts are required.

OPTION A: UPDATE VIA GIT (RECOMMENDED - 4 COMMANDS)
================================================================================

Step 1: SSH into the server and navigate to the application directory:
----------------------------------------------------------------------
cd /path/to/operationsapp
# (Typically: cd /var/www/operationsapp or ~/operationsapp)

Step 2: Pull the latest committed code from repository:
----------------------------------------------------------------------
git pull origin main

Step 3: Rebuild the application container with fresh files:
----------------------------------------------------------------------
docker compose build --no-cache app

Step 4: Restart the app container (keeps database running uninterrupted):
----------------------------------------------------------------------
docker compose up -d app

Step 5: Verify the automatic database migration and health check:
----------------------------------------------------------------------
docker compose logs -f --tail=50 app

(Press Ctrl+C to exit log streaming once you see "Server running on http://0.0.0.0:3000")

1. Database Connectivity Check with resilient retries.
