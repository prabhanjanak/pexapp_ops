OVERVIEW OF THIS UPDATE (v2.2.0 - BOTTLENECK MODULE ENHANCEMENT):
--------------------------------------------------------------------------------
This release implements major enhancements to the Bottleneck Management Module
and Central Operations Directorate communication workflows:

1. FIX BOTTLENECK UPDATE & REFLECTION ISSUE:
   - Root Cause: Missing database columns (department, acknowledged_by, assigned_to,
     history JSONB) and state mutation dropping server responses caused updates in
     Indore, Shivamogga, etc. to not persist or reflect across MHQ.
   - Solution: Added full lifecycle columns to 'bottlenecks' table, automatic diff
     computation on updates, persistent JSONB history audit log, and synchronized
     frontend state update that immediately reflects on both Unit & MHQ dashboards.

2. "RESOLVED BY MHQ" OPTION WITH DEPARTMENT ROUTING FOR UNIT HEADS:
   - Added a dedicated "Resolved by MHQ" action button for Unit Heads.
   - When local units require central MHQ intervention, clicking this action opens an
     interactive modal with a Department Selection Dropdown (Biomedical Engineering,
     Procurement & Supply Chain, IT, Central Operations, QA, etc.).
   - Unit Head selects the responsible MHQ central department and enters intervention notes.
   - Flags the bottleneck with status 'Requires MHQ Intervention', assigns the department,
     and records who requested it and when.
   - Captured in audit history with Unit Head name, selected department, and timestamp.
   - Both Unit and MHQ Dashboards display the assigned MHQ Department badge and requirements.
   - MHQ Directorate dashboard features an instant filter and "Mark Resolved by MHQ" action.

3. UNIT HEAD ACKNOWLEDGEMENT & DEPARTMENT-LINKED EMPLOYEE ASSIGNMENT WORKFLOW:
   - When MHQ raises a bottleneck against a unit (e.g. Arsh Mishra raises for Shivamogga):
   - Respective Unit Head (e.g. Gayatri Shantharam) clicks "Acknowledge" or "Assign Employee".
   - The interactive Accept / Assignment Modal allows:
     * Selecting the responsible Department (e.g. Facility & Maintenance, Patient Care, Operations, etc.).
     * Selecting the corresponding in-charge employee who comes under that department
       (e.g. selecting Facility & Maintenance highlights and links Mr. Kumaraswamy, Facility Manager).
     * Option to immediately begin resolution (Status: "In progress" with 25% progress)
       or keep queued as "Acknowledged".
     * Assigning target deadline date with 1-click presets (+7d, +14d, +30d).
     * Adding action plan / instructions for the assignee.
   - Captures assigned employee name, department, official email, assigned by, and timestamp.
   - Both Unit Head and MHQ Dashboards clearly display the assignment, department, and status.

4. NEW FEATURE: UNIT EMPLOYEE MASTER UNDER SETTINGS:
   - Navigation: Settings → Unit Scopes & Settings → Unit Employee Master.
   - Accessible to IT Administrators, Super Admins, and Operations Directorate.
   - Complete CRUD management: Add employee, edit details, activate / deactivate status,
     reassign unit, associate department, and manage email.
   - Scoped: Only Active employees of that specific unit appear in the Unit Head assignment dropdown.

5. EXPANDED BOTTLENECK STATUS LIFECYCLE:
   - Standardized lifecycle: Raised by MHQ -> Pending Acknowledgement -> Acknowledged ->
     Assigned to Employee -> In Progress -> Requires MHQ Intervention ->
     Resolved by Unit -> Resolved by MHQ -> Completed.

DATABASE NOTE (IMPORTANT):
- Your existing PostgreSQL database and historical records are 100% PRESERVED.
- Automatic schema migration automatically creates 'unit_employees' table and adds
  new columns to 'bottlenecks' table on container boot.
- NO manual SQL scripts are required. Safe and idempotent.

NODE.JS VERSION REQUIREMENT & UPDATE GUIDE (NODE.JS 22 LTS)
================================================================================
REQUIRED NODE VERSION: Node.js >= 20.6.0 (Recommended: Node.js 22 LTS)
Why: React 19, Vite 6, and ES module tsx import (`--import tsx`) require Node 20+.

--> IF RUNNING WITH DOCKER:
    The Dockerfile is already configured with `FROM node:22-alpine`.
    To ensure the host has the latest Node 22 image, simply run:
    docker pull node:22-alpine
    docker compose build --no-cache app
    docker compose up -d app

--> IF RUNNING NATIVELY ON LINUX (UBUNTU / DEBIAN with PM2 or systemd):
    Run these commands to upgrade the server's Node.js to Node.js 22 LTS:

    # 1. Check current node version:
    node -v

    # 2. Add official NodeSource Node.js 22 LTS repository:
    curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -

    # 3. Install Node.js 22 & npm:
    sudo apt-get install -y nodejs

    # 4. Verify the new version:
    node -v   # Should output v22.x.x
    npm -v    # Should output 10.x.x or higher

    # 5. Update PM2 to use the new Node runtime:
    sudo npm install -g pm2
    pm2 update
    pm2 restart ecosystem.config.cjs --env production

--> IF USING NVM (Node Version Manager):
    nvm install 22
    nvm use 22
    nvm alias default 22
    node -v

--> IF RUNNING ON RHEL / CENTOS / ALMALINUX / ROCKY LINUX:
    curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo bash -
    sudo dnf install -y nodejs
    node -v
