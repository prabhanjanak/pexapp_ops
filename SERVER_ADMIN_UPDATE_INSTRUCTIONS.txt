================================================================================
OPTION A: UPDATE VIA GIT (RECOMMENDED - 3 COMMANDS)
================================================================================

Step 1: SSH into the server and navigate to the application directory:
----------------------------------------------------------------------
cd /path/to/operationsapp
# (Typically: cd /var/www/operationsapp or ~/operationsapp)

Step 2: Pull the latest committed code from repository:
----------------------------------------------------------------------
git pull origin main

Step 3: Rebuild the application container with fresh files:
----------------------------------------------------------------------
docker compose build --no-cache app

Step 4: Restart the app container (keeps database running uninterrupted):
----------------------------------------------------------------------
docker compose up -d app

Step 5: Verify the automatic database migration and health check:
----------------------------------------------------------------------
docker compose logs -f --tail=50 app

(Press Ctrl+C to exit log streaming once you see "Server running on http://0.0.0.0:3000")


================================================================================
OPTION B: UPDATE VIA AUTOMATED BASH SCRIPT (ONE COMMAND)
================================================================================

If you have updated files on the server, you can run the provided update script:

chmod +x update.sh
./update.sh


================================================================================
OPTION C: UPDATE VIA ZIP ARCHIVE (IF SERVER HAS NO DIRECT GIT ACCESS)
================================================================================

If the server has no internet access or uses manual file transfer:

Step 1: Upload the fresh project files/zip to the server.

Step 2: Extract over the existing directory (preserves .env and docker data):
----------------------------------------------------------------------
unzip -o pexapp_ops_production.zip -d /path/to/operationsapp
cd /path/to/operationsapp

Step 3: Rebuild and restart the container:
----------------------------------------------------------------------
docker compose build --no-cache app
docker compose up -d app

Step 4: Check logs:
----------------------------------------------------------------------
docker compose logs -f --tail=50 app

HOW THE AUTOMATIC DATABASE UPDATE WORKS (FOR ADMIN AUDIT)
================================================================================
When the 'app' container starts, the startup routine automatically performs:
1. Database Connectivity Check with resilient retries.
2. Safe Schema Migration:
   - ALTER TABLE users ADD COLUMN IF NOT EXISTS emp_id VARCHAR(50);
   - ALTER TABLE users ADD COLUMN IF NOT EXISTS app_access VARCHAR(30) DEFAULT 'both';
   - ALTER TABLE users ADD COLUMN IF NOT EXISTS zone_id VARCHAR(50);
   - ALTER TABLE users ADD COLUMN IF NOT EXISTS department VARCHAR(100);
3. User Upsert (ON CONFLICT DO UPDATE):
   - Adds default role accounts:
     * Zonal In-Charge:      zonal01@sankaraeye.com     (Password: Sankara@123)
     * Department In-Charge: incharge01@sankaraeye.com  (Password: Sankara@123)
     * Internal Auditor:     auditor01@sankaraeye.com   (Password: Sankara@123)
   - Existing staff accounts, bottlenecks, and unit setups remain untouched.
